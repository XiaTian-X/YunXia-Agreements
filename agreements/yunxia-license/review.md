# 软件许可的代表性使用路径

核阅日期：2026-10-19。当前正文：0.9.3审阅草案。本轮在既有路径分析上，按实际传输和实体载体移交明确声明提供方式；原有来源条件及兼容未决项继续核对，未设立自动兼容豁免。

“第三方纳入”指把上游内容用于采用本许可的项目；“本许可输出”指把本许可内容用于其他许可的项目。二者并不对称。并列作品、受同一许可覆盖的衍生组合和替换原有授权，应分别判断；文件夹、进程或项目名称本身不能决定作品关系。

结论分三级：**A 有条件路径**表示原文提供相应方式，尚须以事实落实；**B 需专项核对**表示条件范围或相互关系尚未确认；**C 需另行授权**表示所描述的替代路径超出当前已有权限，须取得足够授权后采用。各等级均不是整项许可或项目的兼容认证。

## 版本与未决风险

GPL 的 `only` 与 `or-later` 依实际授权声明区分。GPL-2.0-or-later 可依其授权选择 GPLv3 后重新核对；GPL-2.0-only 没有这种自动选择。GPL-3.0-or-later 的后续版本选择也以授权和实际存在的版本为依据。包中出现新版许可全文，不等于取得选版权限。[6 §9][7 §14]

临时接收并不当然处于 GPL 的副本传递范围之外。因此，不能仅凭本许可要求临时网络传输附声明，就断言 GPL 不兼容；纯服务器运行、没有相关内容传输，也不能一概视为触发本许可声明。真正待核的是：在 GPL 未要求交付的行为中，本许可是否增加义务，以及该义务能否落入 GPLv3 第 7(b) 条允许的合理法律通知。超出允许范围且须继续承接时，才出现额外限制冲突；GPLv2 也须按其自身条款判断。[6 §0、6][7 §0、2、7、10]

保留原有部分的直接宽松授权，本身不等于违反 copyleft；它不使他人新增代码或整个衍生组合自动改为宽松许可。既有授权继续有效，与另行条款须保留接收者对原有部分的权限，是两个需要分别判断的事项；后者也纳入持续条件及额外限制的专项核对。现稿允许的再许可继续承接来源条件，不能把“可以再许可”解释成“可以删除疑似冲突条款”。本轮对此维持未决，不预设 GPL 或 AGPL 兼容。[7 §5(c)、7、10]

同一次发布能够同时履行条件，也不自动证明整个许可证普遍兼容。应记录后续接收者的许可路径。真正冲突时可核实已有任选路径、取得足够的另行授权，或更换相应内容；改变文件或进程结构是否解决问题，仍须根据实际作品关系判断。采用本许可的权利人与第三方权利人分别负责其授权，不能由项目维护者一并代签。

# 内容类许可的混合使用路径

适用版本：允夏许可证 0.9.3 审阅草案。官方来源核对日期：2026-10-19。

本说明是基于许可文本的条件分析，不是实际项目权属审计或兼容认证。0.9.3 以实际传输与实体载体移交区分声明提供方式，继续按真实内容范围和独立许可选择判断；不自动删除第三方义务，也不提供通用兼容豁免。

## 判读方法

“入向”指将其他许可材料纳入采用本许可的项目；“出向”指将本许可材料用于其他许可项目。先区分：独立收录是各部分分别许可；改编组合须判断新增贡献、原材料及整体分别受哪些条件约束；原材料换证则需要相应权限，不能以替换 LICENSE 文件完成。

判断等级：**A 有条件路径**，指文本提供路径，仍须核对事实；**B 需专项核对**，指组合方式或目标条款影响结果；**C 需另行授权**，指所述使用不能仅依当前授权完成；**D 事实待核**，指缺少具体条款或权属证据。A 不表示其他独立权利已清理。

## 入向：其他许可内容进入项目

| 原材料的确切许可 | 独立收录 | 改编组合及原材料换证 |
|---|---|---|
| CC0 1.0 | A：依有效弃权或后备许可使用 | A：有权许可的新增贡献可用本许可；不能据此收回公众对原材料已有的自由。CC0 不处分专利、商标和他人权利。[1] |
| CC BY 4.0 | A：原材料保留 BY 及适用声明 | A/B：自己的改编贡献可另选许可，但须保留原 BY 条件、修改标记等，并允许接收者遵守 BY；不能把原材料仅改标成本许可。[2] |
| CC BY-SA 4.0 | A：独立部分可各自许可 | B：分享改编时，改编贡献须用 BY-SA 同版或后续版，或 CC 指定兼容许可。直接仅改成本许可属 C；本许可未列入官方名单，不能单方宣布兼容。[3] |
| CC BY-NC 4.0 | A：须满足非商业用途条件 | B/C：自己的新增贡献可另授权限，原材料仍受 NC 约束；商业使用须有其他依据。免费提供不当然属于非商业。[4] |
| CC BY-ND 4.0 | A：可收录未改编材料，依条件署名和提供许可 | A/C：制作、复制改编材料可按原许可进行；对公众分享改编超出该许可授权（C）。必要的技术格式变换不当然构成改编。[5] |
| CC BY-NC-SA / BY-NC-ND 4.0 | A：分别遵守全部要素 | B/C：前者同时适用 NC 和 SA；后者同时适用 NC 和 ND。直接仅改成本许可属 C；不能仅凭“CC”“NC”或“ND”简称判断。[6][7] |

CC 官方说明允许不同许可材料组成合集，合集采用何种许可不改变各原材料许可。因此，项目包含 BY-SA 图片或未改编的 ND 文献，不等于项目所有代码必须改用该许可。反之，把材料放进独立目录，也不能消除已发生的改编或商业使用。[8]

上述判断限定列明版本；旧版本、移植版本及额外授权应分别核对。是否构成改编以适用权利及实际使用为基础；CC 对音乐作品、表演或录音与动态画面同步规定了明确的改编情形。涉及数据库时还须核对各许可第 4 节，不能只判断单个内容是否改动。[2][3][6][7]

例如，程序采用本许可，资料目录收录 BY 文献并保留其许可，可以分别标注。把 BY-SA 原文翻译并融入手册，则须核对该改编及相关贡献的共享条件。目录分隔只能说明材料位置，不能代替对实际组合关系的判断。[2][3][8]

## 出向：本许可材料进入其他许可项目

符合本说明所列许可的独立收录条件时，该路径可列为 A：本许可部分继续履行本许可，其他部分按各自条款。仅依本许可取得的材料即使被再许可，所依赖授权的条件仍适用；目标许可是否容许这种安排属于 B，不能写成“可以任意单一换证”。

尤其，本许可要求移交实体载体副本时随附声明全文，并可能覆盖非公开的个人间交付；BY-SA 4.0 允许合理方式提供全文或链接，且禁止对改编材料施加限制其授权权利的附加条件。由此判断，不能承诺仅凭本许可的再许可条款，就能把整个改编作品无条件转成 BY-SA。主动附全文与要求所有下游持续履行更严格条件应分开判断。公开网络临时传播本身并非区别：CC 的 Share 同样包括公开展示、表演和传播。[3]

有权主体可以对其有权处分的同一材料，明确提供真实、独立的备选授权。使用者选择该路径时，在它覆盖的范围内依其条件取得权限，无须仅靠本许可再许可来实现目标。声明应写明主体、材料及版本、权利范围、确切目标许可和选择关系。若发布者只有受条件约束的再许可权限，换个名称不会消除源条件；独立选择也不能补齐其他贡献者或第三方权利。[2：6(c)、7(a)；3：6(c)、7(a)]

## ODbL 1.0：数据库与内容分层

入向独立数据库合集为 A：ODbL 数据库仍按 ODbL，合集其他独立数据库可分别许可。数据库中每项图片、文字等内容的独立权利须另核，不能由数据库许可代替。[9：1.0、2.4、4.5(a)]

入向改编为 B/C：公开使用衍生数据库须履行共享条件；向新库提取或再利用全部或实质部分可能构成衍生数据库。公开使用由衍生库生成的成果，也可能触发数据库开放及提供机器可读数据库或完整变更材料的义务；成果本身不因生成就成为衍生数据库，但可能需要来源声明。因此，未提供数据库下载不等于没有义务。[9：4.3—4.6]

这里的公开使用按 ODbL 的 Publicly 定义核对自身及控制关系，不限于公开网站。实质部分兼看数量、质量，反复系统提取小部分也可能累计达到相关门槛。[9：1.0]

出向转用 ODbL 为 B：须核对新增内容许可、持续条件与 ODbL 的附加限制规则。入向原库不能由下游直接再许可成本许可；ODbL 的许可选择、兼容路径及授权代理须有对应依据。[9：3.3、4.4、4.7、4.8]

## 自定义模型、数据及商业资产

结论为 D，不按“开放权重”“免费”“可下载”推定许可。逐项核对代码、权重、数据、文档、字体、音视频及服务条款：是否允许所拟商用、修改、训练、部署、托管和再分发，是否有用途、人数、收入或地域条件，以及声明和下游义务。不同项目的同类资产也可能完全不同。

入向使用、在服务器运行和向用户交付资产是不同事实；出向须保证自己的授权不超出来源权限。输出按实际内容与有效约定判断，既不自动继承本许可，也不因称为输出就排除复用内容的义务。本节是核验方法，不是对任何未提供的模型或商业许可作结论。
