# 允夏系列原则

每个具体协议具有稳定ID、设立目的、适用对象和明确条款取舍。新增协议先说明与现有协议的关系；不得仅通过换名复制协议并暗示具有新效果。

协议ID不随显示名称改变。协议、工具、项目内容和记录格式各自维护版本。版本号用于唯一定位，不自动证明兼容；具体影响写入发布说明。

工作正文在agreements维护，历史正文由Git对象保存。registry只记录版本身份、完整提交、取材路径、摘要、审阅和发布事实，不再复制历版正文。tag必须解析到登记的源码提交，不得覆盖既有标签或以标签变化自动更新登记。新引用由agreement_id、version、sha256组成，不能通过额外修订字段覆盖同一正式版本。工具只接受这一引用结构。

发布事实与采用事实分开：维护者发布一份协议，不等于某个项目已采用；安装或更新Skill也不产生授权。协议发布不要求对应Skill已经实现适配，支持程度单独声明。

正式正文保持固定。新条款发布新版本；采用指南、工具规则和解释的更新不自动改变正文和旧项目绑定。停止推荐或维护时保留固定版本的可定位性。

历史资料按用途保留：固定引用、重要设计理由、未决问题和真实来源事实保留；重复归档和过程报告退出日常仓库。模板、表格和工具输出名称是管理方法，不增加协议条件。

审阅绑定确定的材料清单及其摘要，包括正文、定位、设计、采用指南，以及存在的场景、模板和修订基线；批准记录自身、推荐及发布回执不参与递归摘要。审阅者和依据由维护者真实提供，测试通过或历史迁移不能自动生成批准。

版本身份、发布事实、远端可用性与协议维护状态分别记录。同一协议ID和版本不允许改绑源码或正文。发布后的下载失败不抹去已发布事实，停止推荐或撤回也不改写旧项目的采用确认。正式版本和候选是不同身份，即使正文相同也保留各自记录。

构建从固定Git对象读取原字节，不执行历史代码，不使用工作树替代缺失对象。输入清单覆盖版本登记、适配登记、引擎和Skill指令；复制结果逐项与输入快照核对。离线包的文件清单用于一致性核验，可信来源须由安装渠道或外部核验依据保证。
